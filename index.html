01 / 方向

SELECTED DIRECTION

为什么是 3D：把「看见」拆成可以被计算的几何

实验室给我的选项里，无人机、工业测量、11v11、巡航我都能说出兴趣，但只有一个方向我现在就能在自己的笔记本上做出能看的东西来——3D。

  • 3D 方向解决的是机器人的低级但致命的问题：我在哪（位姿/里程计）、周围是什么形状（深度/重建）、目标在哪个位置和姿态（6D 位姿）。这些答错了，后面多聪明的决策都是空转。
  • 它天然是「软件 + 数学」的方向。相机是传感器里最便宜的，剩下的活全在算法里——重投影误差、光束法平差、可微渲染，本质是优化问题。我是软件工程专业，这些我能一行行写下来、跑起来、看结果对不对。
  • 门槛低、反馈快。一个 8GB 显存的笔记本就能跑小场景的 COLMAP、3DGS、NeRF——先把一个小物体重建出来，看到点云在屏幕上转，比在仿真里等一个月更有正反馈。
  • 它正好是 11v11 的地基。多机协同要求每台机器人先知道自己在场地的哪个位置、球在哪，这两件事都是三维视觉在做。所以我把 11v11 写成大二目标，而不是现在硬上。
  • 这条线的历史很清晰，好自学。传统几何（SfM/MVS/SLAM）→ 神经渲染（NeRF、3D 高斯泼溅）→ 视觉几何大模型（DUSt3R、VGGT）。三代方法都开源，都能在 GitHub 上找到原始代码。
多视图几何→神经渲染 / 3DGS→几何大模型→人形机器人感知

我理解的「3D 方向 = 做 CV」

输入
单目 / 双目 / RGB-D 图像、深度相机、激光雷达的原始数据。
中间
特征与匹配 → 相机位姿 → 深度与点云 → 网格与表面 → 语义。
输出
一张能拿来用地形、走路的「地图」，和物体相对于机器人的位置与姿态。
与人形的关系
人形机器人抖动大、视点变化剧烈，视觉既要做状态估计的输入，也要做决策的输入——这正是难的地方，也是我想做的原因。
我现在会什么
Python 能写、C++ 刚起步（WSL2 + Ubuntu 已就绪）、线代在学。坦诚说：还不会任何 3D 视觉算法，但知道第一站该去哪。

04 / 项目雷达

3D / COMPUTER-VISION REPO RADAR

三维视觉方向的开源项目雷达

这是我为「3D 方向」做的一个小工具：脚本从 GitHub 官方接口按 topic 与关键词抓取三维视觉相关的仓库，按星标与「星速」（星标 ÷ 月龄）排序。带「我读过」标记的是我逐个看过、写了中文笔记并给出安装命令的。

—我读过 / 精选
—星速爆发
—合计星标

星速 = 星标 ÷ 仓库月龄；「星速爆发」= 建仓 ≤30 个月且星速 ≥150/月。数据自动生成，点开卡片能看到安装命令。

这批项目是怎么来的（数据管线，点开看）
  1. 用 GitHub REST API 的 /search/repositories 按 topic:3d-reconstruction、topic:gaussian-splatting、topic:visual-slam、topic:depth-estimation 等 16 组检索式抓取，每组按星标倒序取前若干。
  2. 外加 31 个我手工列出的仓库（COLMAP、Open3D、nerfstudio、3DGS、VGGT、DUSt3R、ORB-SLAM3、《SLAM 十四讲》等），逐个查详情接口拿到星标、语言、许可证、最近推送时间。
  3. 检索接口会夹带「沾边但不相干」的高星仓库（人脸识别、扫地机器人、求职资料、网页图形引擎），所以加了相关性关键词过滤 + 一份人工否决清单，被否掉的仓库带原因记在脚本里。
  4. 分类最初按「第一个命中的关键词」判定，结果把 FAST-LIVO2（激光惯性视觉里程计）错分进「3D 高斯泼溅」；改成给名称/描述/topic 打分取最高后才正确。
  5. 结果落盘成 data/projects.js，页面离线也能打开；要刷新数据就重跑一次脚本。
05 / 过程

HOW I USED AI, INCLUDING WHEN I HAD TO CORRECT IT

我是怎么用 AI 把想法做成一个能跑的网页的

要求里写的「关注你如何借助 AI 把想法逐步做成」——那我讲过程，也讲我纠正 AI 的地方。

  • 先定结构，再让 AI 写。我先想清楚页面要回答评审的四个问题（你是谁 / 你折腾过什么 / 你为什么选这个方向 / 你怎么用 AI），把每一节的内容先写成中文要点，再让 AI 做版式与实现。反过来（先让 AI 排版，再往里塞内容）会得到一堆漂亮但没有信息的页面。
  • 不让 AI 编数据。页面上的星标不是它写的，是脚本抓的。我要求「抓真实数据 → 存成文件 → 页面读取」，这样即使断网、即使接口限额用完，页面里的数字也还是真的。
  • AI 的第一版被我退回两次。第一次它打算用网页爬虫抓 GitHub，我改成用官方 API（有结构化字段、不会被封）；第二次它没处理接口限额，我要求改用本机已授权的令牌并把结果缓存下来。
  • 发现 AI 的筛选逻辑不严，我自己补规则。抓回来 138 个仓库里混着人脸识别、扫地机器人、求职资料这类高星但不相关的项目——我把「相关性关键词 + 人工否决清单」加进脚本，重抓到 116 个，每个都得说得出为什么属于三维视觉。
  • 发现分类错了，我要求改成打分。激光惯性视觉里程计被归进「3D 高斯泼溅」，因为脚本只看第一个命中的关键词。改成按名称、描述、topic 加权打分后归到「SLAM 与定位」。
  • 视觉上我有自己的判断。我不想要那种「渐变背景 + 三张等宽卡片」的模板页：所以点云是用真实投影算出来的、颜色是真实的深度伪彩；正文用纸色和衬线，数据一律等宽字体，让「数字是真的」这件事一眼看得出来。
